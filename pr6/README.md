Консольное приложение на PySpark.Добавляет Kafka + Spark Structured Streaming из ЛР6.

## 1. Структура проекта

```text
LR6/
├── main.py
├── requirements.txt
├── docker-compose.yml
├── README.md
└── data/
    ├── orders_clean/
    ├── order_items_clean/
    ├── products_clean/
    ├── customers_clean/
    ├── reviews_clean/
    └── output/
```

## 2. Подготовка данных

Скопируйте очищенные Parquet-данные из ЛР3 в папку `data`. Приложение ожидает папки:

- `orders_clean`
- `order_items_clean`
- `products_clean`
- `customers_clean`
- `reviews_clean`

## 3. Установка

Требуется Python и Java, совместимая с установленной версией Spark. В терминале из папки проекта выполните:

```bash
python -m venv .venv
```

Windows:
```bash
.venv\Scripts\activate
```

Установка библиотек:
```bash
pip install -r requirements.txt
```

Kafka-коннектор Spark загружается через Maven при первом запуске. Для Spark 4.x приложение использует Scala 2.13, для Spark 3.x — Scala 2.12.

## 4. Запуск Kafka

Установите и запустите Docker Desktop, затем в папке проекта выполните:

```bash
docker compose up -d
```

Kafka будет доступна приложению по адресу `localhost:9092`.

Проверить контейнер:
```bash
docker compose ps
```

Остановить Kafka:
```bash
docker compose down
```

Для полного удаления данных Kafka:
```bash
docker compose down -v
```

## 5. Запуск приложения

```bash
python main.py
```

При запуске приложение читает очищенные Parquet-таблицы из `data`.

## 6. Пункты меню

| Пункт | Возможность |
|---|---|
| 1 | Просмотр загруженных данных |
| 2 | Анализ продаж по месяцам |
| 3 | Анализ продаж по категориям |
| 4 | Анализ заказов по регионам |
| 5 | MapReduce: частотность слов в отзывах |
| 6 | Экспорт аналитических результатов в CSV и Parquet |
| 7 | Обучение Logistic Regression для тональности отзывов |
| 8 | Предсказание с помощью сохранённой ML-модели |
| 9 | Kafka Producer: отправка заказов в топик `olist-orders` |
| 10 | Spark Structured Streaming: чтение Kafka, фильтрация и агрегация по минутным окнам |
| 11 | Просмотр сохранённых результатов потоковой обработки |

## 7. Как выполнить потоковую обработку

1. Запустите Kafka через `docker compose up -d`.
2. Запустите приложение: `python main.py`.
3. Выберите пункт **9**. Введите число событий или нажмите Enter для отправки всех заказов.
4. После завершения Producer выберите пункт **10**. Приложение начнёт читать события из Kafka.
5. Остановите обработку сочетанием `Ctrl+C`.
6. Выберите пункт **11**, чтобы посмотреть сохранённые результаты.


# Бизнес-план по созданию инфраструктуры больших данных для интернет-магазина

## 1. Описание предприятия

В качестве предприятия рассматривается интернет-магазин, работающий по модели электронной коммерции. Компания получает заказы от покупателей, взаимодействует с продавцами, обрабатывает платежи, организует доставку товаров и собирает отзывы клиентов.

В процессе работы накапливается большое количество информации: сведения о заказах, товарах, покупателях, оплате, доставке и отзывах. Эти данные можно использовать для анализа продаж, оценки качества обслуживания и улучшения работы интернет-магазина.

Для эффективной обработки такой информации предлагается создать инфраструктуру больших данных на основе Apache Spark и Apache Kafka.

## 2. Цели создания инфраструктуры

Основная цель проекта — создать систему сбора, хранения и обработки больших объёмов данных интернет-магазина.

Основные задачи:

- автоматизация сбора информации о заказах;
- обработка данных в режиме потоковой передачи;
- анализ продаж и выручки;
- определение наиболее популярных категорий товаров;
- анализ заказов по регионам;
- анализ отзывов покупателей;
- прогнозирование тональности отзывов с помощью машинного обучения;
- предоставление руководству информации для принятия решений.

## 3. Предлагаемая архитектура

Для реализации проекта предлагается использовать следующие технологии:

| Технология | Назначение |
|---|---|
| Python | Разработка приложения и обработка данных |
| Apache Kafka | Передача событий о заказах |
| Apache Spark | Распределённая обработка данных |
| Spark Structured Streaming | Обработка поступающих событий в реальном времени |
| Spark MLlib | Построение моделей машинного обучения |
| Parquet | Хранение обработанных данных |
| Docker | Запуск и настройка Kafka |

Общая схема работы системы:

1. Интернет-магазин формирует события при создании новых заказов.
2. События передаются в Apache Kafka.
3. Apache Spark получает данные из Kafka.
4. Spark выполняет проверку и очистку поступившей информации.
5. Spark Structured Streaming рассчитывает количество заказов, выручку и средний чек за определённые временные интервалы.
6. Результаты сохраняются в формате Parquet.
7. Аналитическое приложение использует сохранённые данные для построения отчётов.

Дополнительно исторические данные интернет-магазина обрабатываются с помощью Apache Spark. На их основе выполняется анализ продаж, категорий товаров, регионов и отзывов покупателей.

## 4. Этапы реализации проекта

Создание инфраструктуры предлагается разделить на несколько этапов.

**Этап 1. Подготовка данных**

Необходимо собрать информацию о заказах, товарах, покупателях, доставке и отзывах. Далее выполняется очистка данных от пропусков, ошибок и дубликатов.

**Этап 2. Создание системы передачи данных**

Настраивается Apache Kafka. Для передачи информации используется отдельный топик, в который поступают события о заказах.

**Этап 3. Настройка потоковой обработки**

Apache Spark подключается к Kafka и обрабатывает поступающие события. Выполняется фильтрация некорректных записей и расчёт основных показателей продаж.

**Этап 4. Создание аналитической системы**

На основе накопленных данных реализуются отчёты по продажам, категориям товаров и регионам. Результаты сохраняются в Parquet.

**Этап 5. Внедрение машинного обучения**

С помощью Spark MLlib создаётся модель классификации отзывов покупателей на положительные и отрицательные. Это позволит оценивать общее отношение клиентов к товарам и качеству обслуживания.

**Этап 6. Тестирование и запуск**

Проводится проверка корректности передачи, обработки и хранения данных. После успешного тестирования система может использоваться для анализа работы интернет-магазина.

## 5. Ожидаемые результаты и преимущества

После внедрения инфраструктуры предприятие получит следующие возможности:

- более быструю обработку информации о заказах;
- получение актуальных показателей продаж;
- анализ выручки и среднего чека;
- выявление наиболее популярных товаров и категорий;
- определение регионов с наибольшим количеством заказов;
- использование машинного обучения для автоматической классификации отзывов;
- снижение количества ручных операций при подготовке аналитических отчётов.

В результате руководство интернет-магазина сможет быстрее получать необходимую информацию и принимать решения на основе данных.

## 6. Возможные риски

При внедрении инфраструктуры могут возникнуть следующие проблемы:

- увеличение объёма данных и нехватка места для их хранения;
- сбои при передаче информации через Kafka;
- недостаточная производительность оборудования;
- ошибки при обработке данных;
- необходимость обслуживания и контроля работы системы.

Для снижения рисков необходимо регулярно создавать резервные копии, контролировать состояние сервисов, проверять качество поступающих данных.

## 7. Заключение

Предлагаемое решение основано на использовании Apache Kafka для передачи событий, Apache Spark для обработки информации, Spark Structured Streaming для потоковой аналитики и Spark MLlib для машинного обучения.
Внедрение подобной инфраструктуры позволит интернет-магазину эффективнее использовать накопленные данные, улучшить контроль продаж и повысить качество принимаемых управленческих решений.
